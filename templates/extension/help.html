Skill Forge Gate 面板

这个扩展只做一件事：把本地面板当成普通文件打开。它没有任何权限。

点了图标没反应？还差一个开关

浏览器默认不允许扩展打开 file:// 本地文件，需要一个手动勾选的开关。这个开关没法由扩展申请，只能你自己开一次，之后一直有效。

  1. 把下面这个地址复制到地址栏，回车：
（也可直接在扩展列表里找到「Skill Forge Gate 面板」）
  1. 点开「Skill Forge Gate 面板」的「详细信息」
  2. 把「允许访问文件 URL」打开（不同浏览器版本文案略有出入，找带「文件」和「允许」的那一项即可）
  3. 回到工具栏，再点一次扩展图标 —— 面板就开了
红色「!」是上一次点击留下的记号，不是开关的实时状态 —— 浏览器不提供"开关被切换"的通知，扩展在结构上就感知不到你刚打开它。 所以：打开开关之后再点一次图标，面板就开了，记号也会消。

为什么它什么权限都不要

面板渲染的是从 GitHub 拉来的、别人写的描述文本。这类文本永远该被当作不受信输入 —— 面板内部已经有四层转义防线，但"防线很多"和"不可能被绕过"是两回事。

所以这里做了个取舍：

  • 面板待在普通标签页里：万一有人靠描述文本突破了防线，攻击者拿到的是一组 有边界的本地 HTTP 接口（能逐条枚举、逐条加固）。
  • 面板要是待在扩展里：同一次突破会直接够到 chrome.* —— 能读你所有标签页、能用扩展身份发跨域请求、能改别的扩展。

代价是每次打开会多一个标签页，而不是一个小弹窗。这个代价是故意付的。

它不做什么

  • 不读取任何网页内容
  • 不注入脚本到任何页面
  • 不联网（面板连本地 bridge 是面板自己的事，跟扩展无关）
  • 不读取、不保存任何密钥 —— 密钥存在 Windows 凭据管理器里，全程不经过浏览器
